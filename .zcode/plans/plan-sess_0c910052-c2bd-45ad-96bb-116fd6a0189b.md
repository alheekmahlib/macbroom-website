## الخطة: ميزة دعم/تواصل متكاملة (Smart Support System)

دمج 3 مفاهيم في نظام واحد: **مُبلّغ أخطاء استباقي** + **زر مساعدة عائم** + **مركز تذاكر**، مع تخزين مزدوج في Supabase و Formspree.

---

### البنية المقترحة

```
┌─ زر مساعدة عائم (Help Widget) ────────────────────────────┐
│  في كل الصفحات (أسفل اليمين)                              │
│  ├─ 🔍 بحث فوري في FAQ                                    │
│  ├─ 🐛 أبلغ عن خطأ (نموذج ذكي بالسياق التلقائي)           │
│  └─ 💬 تواصل معنا                                         │
└────────────────────────────────────────────────────────────┘
       │
       ▼ يحفظ في
┌─ Supabase: جدول support_tickets ──┐  ┌─ Formspree: إيميل فوري ─┐
│  ticket_id, email, type, subject,  │  │  نفس البيانات تُرسل       │
│  message, context (page/url/ua),   │  │  لإيميل الدعم            │
│  status, created_at                 │  └──────────────────────────┘
└─────────────────────────────────────┘
       │
       ▼ يُعرض في
┌─ صفحة /support + قسم في /profile ─────────────────────────┐
│  قائمة التذاكر السابقة + حالتها (open/answered/closed)    │
└────────────────────────────────────────────────────────────┘

┌─ مُبلّغ الأخطاء الاستباقي (في صفحات profile/signin) ──────┐
│  عند ظهور خطأ → زر صغير 'Report' يفتح نفس النموذج الذكي   │
│  مع تعبئة نوع الخطأ تلقائياً                               │
└────────────────────────────────────────────────────────────┘
```

### جدول Supabase: `support_tickets`

سأعطيك SQL لتطبيقه في لوحة Supabase:
```sql
CREATE TABLE support_tickets (
  id uuid DEFAULT gen_random_uuid() PRIMARY KEY,
  email text NOT NULL,
  type text NOT NULL CHECK (type IN ('general','bug','billing','feature')),
  subject text,
  message text NOT NULL,
  context jsonb,
  status text DEFAULT 'open' CHECK (status IN ('open','answered','closed')),
  user_id uuid REFERENCES auth.users(id),
  created_at timestamptz DEFAULT now(),
  updated_at timestamptz DEFAULT now()
);
ALTER TABLE support_tickets ENABLE ROW LEVEL SECURITY;
CREATE POLICY "Users read own tickets" ON support_tickets
  FOR SELECT TO authenticated USING (auth.jwt() ->> 'email' = email);
CREATE POLICY "Anyone can create tickets" ON support_tickets
  FOR INSERT TO anon, authenticated WITH CHECK (true);
```

### الميزات المبتكرة في التفاصيل

1. **السياق التلقائي**: النموذج يلتقط تلقائياً (صفحة، URL، User Agent، وقت) — المستخدم لا يصفها
2. **Pre-fill ذكي**: إن كان المستخدم مسجّلاً، يُملأ الإيميل تلقائياً
3. **بحث FAQ فوري**: الـ widget يبحث في الأسئلة الشائعة أولاً قبل التواصل
4. **زر "Report" بجانب الأخطاء**: بدل رسالة عادية، زر استباقي
5. **عرض التذاكر**: المستخدم يرى تذاكره وحالتها (تشعر بأن هناك نظام حقيقي)
6. **Dual storage**: Supabase للحفظ + Formspree للإيميل الفوري (لا تخسر تنبيهاً)

---

### الافتراضات والقيود
- الموقع static export — لا API routes، كل شيء client-side
- Supabase client هو anon (لا service role) — آمن
- RLS سيسمح بـ INSERT من أي شخص (للزائرين) و SELECT للمستخدم المصادق على تذاكره فقط
- Formspree موجود (`mnjwnorw`) ويعمل — سأُعيد استخدامه

### ما لن ألمسه
- ❌ لا GitHub issues تلقائية (تحتاج Edge Function — سابقاً)
- ❌ لا live chat (يحتاج WebSocket/طرف ثالث)
- ❌ لا تغييرات على Pricing/Download

هل أبدأ التنفيذ؟ سأطبّق كل الملفات ثم أعطيك SQL لتطبيقه في Supabase، ثم نرفع معاً.
